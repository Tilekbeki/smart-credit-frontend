# Правила разработки и ревью frontend

## Стек и границы

- React + Vite, JavaScript (`.js` / `.jsx`), CSS и `@alfalab/core-components`.
- Сохраняйте существующий стек и визуальный стиль. Миграции на Next.js, TypeScript,
  Tailwind и новые зависимости требуют конкретной задачи.
- Делайте изменения в пределах задачи; исправления поведения важнее косметических
  перестановок файлов и переименований.

## Ответственность модулей

- `src/pages/` — страницы и самостоятельные экраны, включая разделы кабинета и чат.
  У каждого экрана своя папка с `index.jsx` и `styles.css`. Маршрутные страницы
  подключаются в `src/pages/index.jsx`, внутренние экраны — в кабинете.
  `src/main.jsx` отвечает только за запуск React и подключение общих стилей.
- `src/components/` — выделенные UI-компоненты, PascalCase. Не помещайте в них
  HTTP-запросы, правила кредитования и преобразование DTO.
- `src/hooks/` — состояние React и эффекты с корректными зависимостями и очисткой.
- `src/services/` — сценарии работы с API и browser storage; HTTP-контракт — в `src/api.js`.
- Предметные модули (`application-form.js`, `journey.js`, `contacts.js`,
  `bank-review.js`, `chat-recommendations.js`) — чистые функции без React и storage.
- `src/utils/` — общие чистые функции; `src/config/` — маршруты и справочники.
- Сначала ищите существующую функцию. Используйте общие проверку сумм и подготовку
  DTO для формы и чата, форматирование рублей и справочники целей/документов.
- Для новых переиспользуемых модулей предпочитайте именованные экспорты. Сохраняйте
  существующие default-экспорты компонентов; они также подходят для `React.lazy`.
- `index.js` нужен только при наличии осмысленного публичного API папки. Не создавайте
  barrel-файлы, алиасы и абстракции только ради оформления.

## Маршруты, стили и производительность

- Адреса страниц берите из `src/config/pages.js`. Для текущих двух статических
  маршрутов достаточно точного сравнения; библиотека маршрутизации не требуется.
- Сохраняйте CSS-подход и Core Components. Проверяйте контраст, подписи полей,
  клавиатуру, фокус, небольшие экраны и `prefers-reduced-motion`.
- Кабинет и инструменты сотрудника загружайте по необходимости; для отложенных
  модулей показывайте загрузку и понятное восстановление после ошибки.
- Загружайте необязательные данные при открытии соответствующего сценария.
- Используйте `useLayoutEffect` только для синхронной работы с DOM перед отрисовкой,
  например прокрутки чата. Для API и обычных эффектов — `useEffect`.
- Не применяйте ответы устаревших запросов после изменения параметров или ухода с экрана.

## Контракт кредитного пути

- Сверяйте DTO и HTTP-коды с backend `api/openapi.yaml` и `api/FRONTEND_INTEGRATION.md`.
- Гостю доступна рекомендация типа продукта, а не персональная ставка или одобрение.
  Регистрацию и банковские операции, которых нет в API, не имитируйте как реальные.
- Разделяйте права гостя, клиента и сотрудника. По явному требованию пользователя
  JWT сохраняется в `localStorage` через `services/session-storage.js` до своего срока
  действия. При восстановлении проверяйте его через `/me`; роль и компанию берите
  с сервера. Не сохраняйте туда OTP и финансовые данные. Выход и `401` очищают сессию;
  сетевой сбой при восстановлении должен позволять повторную загрузку без нового OTP.
- Пустое денежное поле черновика передавайте как `null`; явный ноль для выручки и
  расходов допустим. Денежные значения — целые рубли в пределах контракта.
- Сохраняйте ввод при конфликтах версий и лимите черновиков. После известного
  создания заявки ошибка submit не должна создавать ещё один черновик автоматически.
- Статусы, обязательные документы и итоговое решение определяет backend.
  Рекомендация и предварительный расчёт не равны кредитному решению или выдаче денег.

## Проверка и завершение

- Для изменений логики добавляйте проверки поведения: DTO, границы, сохранение ввода,
  ошибки, конфликты и переходы. Для перемещения JSX достаточно сборки и проверки UI.
- Выполняйте `npm test`, `npm run build`, `git diff --check`.
- При изменении входа, чата или заявки проверяйте соответствующий путь в браузере.
- Зависимости и экспорты удаляйте только после проверки реального использования;
  инструменты поиска неиспользуемого кода применяйте по необходимости.
- Не редактируйте `node_modules/` и `dist/` вручную. Не коммитьте токены, `.env` и секреты.
- Указания пользователя о ветке, коммите и push имеют приоритет; не создавайте PR,
  если пользователь попросил push непосредственно в `main`.
