# Проверка клиентского и банковского пути — 26.10.2026

## Стенд и способ проверки

- Frontend: React/Vite, исходная версия `d89a596` и два исправления этого прогона.
- Backend: `10da306`, миграции 1–12, отдельная PostgreSQL 16 с чистыми синтетическими профилями.
- Scoring: `60f0c66`, настоящая модель `logreg_v1`, HTTP-сервис Python.
- Браузер: встроенный Chromium, фактический viewport 1280 × 720.
- UI-проходы выполнены через кнопки, формы и файловый диалог. Для подготовки
  одобрения/отказа/контроффера/ручного рассмотрения использовались настоящие API
  создания и отправки заявок, без подмены ответов или изменения статусов в БД.
- Дополнительно выполнены 47 HTTP-проверок контрактов и прав на запущенном API.
  JWT оставались в памяти тестового процесса; токены и OTP не включены в артефакты.

Это покрытие основных веток и граничных условий, а не доказательство проверки
каждой возможной комбинации вводимых значений.

Временные 20 черновиков для проверки лимита удалены. Итоговые синтетические
заявки оставлены как примеры состояний. После проверки scoring снова запущен и
отвечает на `/health`.

## Исправленные ошибки

1. **Действия при неразрешённом конфликте.** После 409 серверная версия формы
   считалась неизменённой, поэтому можно было отправить её до выбора между
   серверной и сохранённой локальной копией. Сохранение и отправка теперь
   блокируются до явного разрешения конфликта. Проверено повторным UI-проходом:
   обе кнопки disabled, затем локальная сумма восстанавливается и сохраняется.
2. **Несогласованная техническая остановка.** При processing.state=failed заголовок
   и следующий шаг продолжали сообщать об идущей оценке. Теперь они показывают
   остановку и необходимость технической проверки, сохраняя правильный этап.
   Повторный UI-проход и тесты проверяют prechecks/scoring/decision; финальное
   кредитное решение имеет приоритет над устаревшими техническими данными.

## HTTP и автоматические проверки

47 HTTP-проверок прошли на настоящем API:

- права гостя, клиента, сотрудника; недоступность чужой заявки, истории, решения и файла;
- приватность черновиков и внутренних комментариев;
- автоматические approved/counter_offer/rejected/manual_review;
- неверная версия, дробные/отрицательные деньги, неизвестные поля, явные нули и null;
- неполная анкета, удаление своего draft и 404 после удаления;
- обязательная выписка, загрузка PDF и побайтовое совпадение скачанного файла;
- обязательный Idempotency-Key, повтор отклонения, другое тело с тем же ключом,
  противоположный ответ на уже закрытое предложение;
- защита финансовых полей профиля и конфликт контактов.

`npm test`: **50/50**, включая два новых регрессионных теста. `npm run build` и
`git diff --check` проходят. Пагинация, испорченное/истёкшее хранилище сессии,
protected 401 и сетевые ошибки дополнительно покрыты существующими unit-тестами.

Общий `scripts/smoke.py` также прошёл через Vite proxy → Go → Python: новая заявка
первого клиента, выписка второго клиента, окончательные решения и повторный вход.

## Как воспроизвести основные решения

Для клиента `+79990000001`, продукта turnover и цели stock:

| Исход | Сумма | Месяцы | Выручка / расходы в месяц |
| --- | ---: | ---: | ---: |
| Одобрение | 500000 | 12 | 2400000 / 1500000 |
| Отказ | 500000 | 12 | 1000000 / 1000000 |
| Другие условия | 1500000 | 12 | 600000 / 300000 |
| Ручное рассмотрение | 1400000 | 12 | 10000000 / 8800000 |

Создайте новую заявку для каждого исхода, выберите продукт и сохраните черновик.
Отправьте его, дождитесь обработки. Для ручного исхода войдите как `…004`, найдите
заявку в очереди, заполните внутренний комментарий, проверьте и подтвердите
решение. Вернитесь к клиенту и откройте тот же номер заявки.

## Ограничения и оставшийся риск

- **В API нет операции перезапуска исчерпанной технической обработки.** После
  processing/failed одного восстановления scoring недостаточно, чтобы гарантировать
  повтор старой заявки. Нужен согласованный с backend механизм восстановления
  очереди. Текущий UI честно показывает техническую остановку, а не отказ или
  успешное завершение. Это отдельный вопрос к backend до полноценной эксплуатации.
- Docker отсутствовал в среде проверки. Все сервисы проверены нативно вместе;
  YAML общего Compose разобран, но сборка Docker-образов и запуск Compose здесь
  не выполнялись. В общем репозитории есть CI для `docker compose config`, сборки
  и smoke; результат удалённого CI не входит в этот локальный отчёт.
- Событие скачивания встроенного браузера завершилось ошибкой инструмента.
  Файл проверен через настоящий authenticated HTTP endpoint и побайтовое
  сравнение; сохранение через системный диалог браузера не подтверждено.
- Запрошенный мобильный viewport не применился: DOM и снимок остались 1280 × 720.
  Проверка на реальном мобильном размере, Safari/Firefox и полноценный аудит
  доступности остаются вне подтверждённого покрытия.
- Реальные SMS, регистрация новых компаний, интеграции ФНС/БКИ, договор,
  электронная подпись и выдача средств в эту синтетическую проверку не входят.
