# Путь клиента со счётом и без счёта

Проверено 24 октября 2026 года по публичным страницам банков. Ниже описаны только видимые условия и опубликованные инструкции. Экраны после авторизации, реальные решения и сроки не проверялись. Страницу Альфа-Банка удалось изучить по индексированной копии официального сайта; прямое открытие в браузере завершилось ошибкой сертификата.

Т-Банк [прямо разделяет в справке](https://www.tbank.ru/business/help/loans/turnover/get-turnover/) маршруты «со счётом» и «со счётом в другом банке». Общая закономерность: отсутствие счёта не блокирует первое полезное действие. Источник оборотов при этом различается: свои обороты банк может видеть, обороты неклиента — только после предоставления выписки или иного подтверждённого источника. Введённая клиентом цифра может помочь предварительному подбору, но её нельзя обозначать как подтверждённые банком обороты.

## Целевой путь и текущее состояние продукта

1. Учебный профиль компании уже содержит серверный источник финансовых данных. Пользователь может дополнительно указать банк счёта в боковом меню; этот выбор хранится локально в браузере и служит подсказкой, а не подтверждённым серверным признаком заявки.
2. **Есть счёт:** показать уже доступные банку сведения и их источник, предложить подтвердить или исправить то, что клиент вправе менять. Не требовать выписку по счёту Альфы только ради подтверждения известных банку оборотов. Если данных не хватает, назвать конкретный пробел.
3. **Нет счёта:** позволить узнать предварительную доступность продукта, создать и отправить заявку без открытия счёта. Запросить ИНН/регистрационные сведения и выписку по счёту другого банка для проверки оборотов; до получения выписки явно маркировать введённые суммы как оценку клиента. Показать причину запроса документа и сохранить его в той же заявке.
4. Для обоих путей отделять подбор от банковского решения, сохранять черновик и показывать статус/следующее действие. Сейчас после решения можно принять или отклонить предложение; принятие даёт учебный статус `signed`. Открытие счёта и выдача не моделируются как завершённые операции. Если они появятся позже, их надо подтверждать серверным состоянием.

В текущем публичном Go API нет поля `bankRelationship`. Источник финансовых
данных и необходимость `BANK_STATEMENT` определяются backend; требование выписки
возвращается при submit, а файл загружается в ту же заявку. Предзаполненные числа
учебного профиля не доказывают реальную банковскую проверку оборотов. Для
полноценного продукта ещё нужны анализ содержимого выписки, регистрация новой
компании, открытие счёта и выдача. Текущий Go backend уже сохраняет кредитное
решение и ответ клиента.

## Текущая интеграция Go API (26 октября 2026)

В main backend нет публичного `bankRelationship`. Во фронте клиент может необязательно указать банк счёта в боковом меню; выбор хранится в текущем браузере отдельно для каждой компании. Это заявленная информация для подсказок, а не подтверждение источника оборотов. Требование `BANK_STATEMENT` определяет submit и его `422 details`. Наличие внешнего счёта само по себе не блокирует заявку на стороне frontend.

Данные financials доступны в профиле компании. Раздел «Контакты и данные» позволяет явно создать новую заявку с этими значениями и проверить их. Контакты пользователя и компании сохраняются через API с разными версиями; номер входа не изменяется при редактировании контактного телефона компании.
