# Умный кредитный кабинет — frontend

React/Vite интерфейс для Go API кредитного конвейера. Контракт находится в ветке
[`feat/go-backend`](https://github.com/Tilekbeki/smart-credit-backend/tree/feat/go-backend)
репозитория backend: `api/FRONTEND_INTEGRATION.md` и `api/openapi.yaml`.

Сейчас работают отдельная страница кабинета `/cabinet`, вход с синтетическим
профилем в один шаг или по номеру и OTP, выбор продукта, предварительная
рекомендация, несколько приватных черновиков, загрузка документов, отправка заявки
и просмотр статуса с историей обработки. Компании и данные синтетические.
Решение по кредиту, принятие предложения и выдача пока не реализованы в Go API;
интерфейс не представляет эти действия как завершённые банковские операции.

## Локальный запуск

1. В репозитории backend переключитесь на `feat/go-backend` и запустите
   `DEMO_OTP_CODE=1221 docker compose up -d --build`, чтобы сохранить
   согласованный тестовый код. Дождитесь ответа `200` от
   `http://localhost:8080/ready`. Backend поднимает PostgreSQL автоматически.
2. В этом репозитории выполните:

   ```sh
   npm ci
   npm run dev
   ```

3. Откройте адрес Vite из терминала. Кнопки на лендинге ведут в `/cabinet`;
   там можно выбрать синтетическую компанию и продолжить без внешнего SMS.
   Ручной вход по номеру и коду доступен как дополнительный сценарий.
   `/api` проксируется на Go backend по
   `http://127.0.0.1:8080`, поэтому настройка CORS не требуется.

Для быстрого входа фронтенд запрашивает и проверяет OTP сам, используя код
`1221`, заданный при запуске backend. Этот режим предназначен только для
синтетических данных хакатона: код находится в клиентской сборке и не является
секретом. Для ручного входа выберите номер из API, запросите код и введите
значение `DEMO_OTP_CODE`. Настоящее SMS не отправляется: backend пока принимает
только `profileId` и выдаёт тестовый OTP.
JWT хранится только в памяти страницы; после обновления страницы или истечения
сессии войдите снова.
Профиль сотрудника банка пока не имеет доступного клиентского сценария.

## Сценарий проверки интерфейса

1. На лендинге нажмите «Начать подбор», на `/cabinet` выберите синтетическую
   компанию и продолжите. При запуске backend командой выше код `1221`
   проверяется автоматически; получение SMS для сценария не нужно.
2. Выберите цель «Товары и сырьё», проверьте сумму, срок и подставленные
   финансовые данные, нажмите «Рассчитать варианты». В карточках видны
   предварительные причины подбора и доступность продукта.
3. Выберите подходящий продукт и сохраните черновик. Список готовности покажет
   сохранённые поля, известные требования к документам и следующий шаг.
4. Вернитесь в «Мои заявки» или выйдите и войдите снова: «Продолжить заявку»
   открывает тот же черновик. При необходимости приложите синтетический PDF,
   PNG или JPEG. Для инвестиционного кредита счёт на оборудование обязателен;
   выписку для оборотного кредита сервис может запросить при отправке.
5. Отправьте заявку и откройте её историю. Статус и этапы читаются из backend,
   оставшиеся черновики не меняются. Окончательное решение и выдача пока не
   реализованы; эти действия в интерфейсе не имитируются.

Сравнение публичных банковских сценариев и приоритеты развития описаны в
[UX-бенчмарке](docs/UX_BENCHMARK.md). Сторонние компоненты и смоделированные
интеграции перечислены в [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md).

## Проверка

```sh
npm test
npm run build
```

Интерфейс использует [Alfa Core DS](https://core-ds.github.io/core-components/master/?path=/docs/intro--docs).
Иллюстрация главного экрана предоставлена заказчиком. Pinterest-ссылка
использована как визуальный референс; сторонний ролик не копировался.
